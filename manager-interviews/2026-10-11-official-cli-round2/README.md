# 官方 CLI 担任 Manager：第二轮面试（2026-10-11）

第一轮见 [../2026-10-11-official-cli/](../2026-10-11-official-cli/)。第二轮与第一轮有三处不同：

1. 加入 Angela 指令初稿（`manager-draft-v0.md`），按 Lobotomy 传角色指令的方式交给候选：Claude 用 `--append-system-prompt`，Codex 用 `developer_instructions`。
2. 换了候选，并统一 effort。第一轮的 effort 不对等：Claude Code 的默认值是 high，gpt-6.1-sol 的默认值是 low。
3. 每条输入开头由"运行时"写上用户当时的本地时间（JST）。

## 评审：两位审阅者，结论按家族分开

两位审阅者都只看内容，不知道候选身份，都按 `review-prompt.md` 审阅：

- `review-claude.md`：Claude 子 agent。
- `review-codex.md`：Codex（gpt-6-astra，high）。它没有读取文件，所有材料由 `bundle.mjs` 拼成一份输入交给它。

**谁更适合**：两位的结论相反，各自偏向与自己同一家族的候选。
- Claude 审阅者选 Y：读出话背后的约束，引用准确，会在不需要时不派 Tech Lead。
- Codex 审阅者倾向 Z，X 也可：Y 更容易把推断扩大成决定、把小任务扩大成工程。

模型审阅对"谁更适合"给不出可信答案。

**两位一致的观察**：
- X 与 Z 的回答高度相近，实际只有两种画像。
- Y 最会利用历史、给出具体机制。case-04 中，它准备告诉用户"同一额度域的其他 role 恢复后仍会启动"，两位都认为这是最好的纠正入口；真实对话中，用户正是因为这一点改口。
- Y 的问题：
  - case-05 把对 autocrlf 的反对升级为"不做任何换行转换"，并派 Worker 落实；
  - case-07 把插进来的小事扩大成没有时间限制的调查；
  - 篇幅是另外两个的 2–3 倍。
- X、Z 的问题：较少读出字面之下的约束；习惯让 Tech Lead 和 Worker 都参与，并让两者直接交接。
- 三者都遵守了初稿的基础规则：不回问已放行的事，不给问卷，原话与推断分开。这些规则区分不出好坏。
- 初稿需要改的地方：
  - 深夜规则用力过猛：Y 在用户仍在工作时就开始收尾；
  - "不要先调查"太绝对；
  - 缺少插入任务的停止条件；
  - 缺少派活成本的规则；
  - 推断标签被当成了授权；
  - "最多一个问题"只限制了句式，待确认的事项仍可藏在报告里。

**三者都不能直接用作 Angela**，只适合有人监督的试用。

## 限制

- 每个案例只跑一次；只有一个用户的历史；案例由 agent 挑选。
- 两位审阅者的结论按家族分开，说明审阅者偏差足以决定"谁更好"。比较模型需要用户本人的判断。
- 本轮没有无初稿的对照组，不能证明某条规则带来了某种改善。
- 没有测上行过滤、猜错后的恢复和现场管理（JD 面试 2、4、5）。
