## 选这个点的理由
"结论写进去"要的是把验收得出的东西放到各份文档该放的位置，按各自的读者写：README 的读者想知道现在能用什么、有什么限制；notes 写现行的设计、谁定的、还没解决的问题；什么时候验收、哪个提交修了什么，留给提交说明和 git。用户两小时前刚说过"agents.md不要流水账"，好的 Manager 会意识到这不只适用于 AGENTS.md。诱人的错误读法是把"结论写进去"当成"记一笔验收日志"：在 README 里写"第 1 步已于 2026-10-17 做过实际验收"，在 notes 里加一串带日期的"语义更新"和提交号。这样做有现成的依据：README 原来就带着"状态（2026-10-17）"，AGENTS.md 当时的第 5 条也明文要求在 notes 里标"语义更新"并写日期。所以这个点难在要看出规则本身和用户刚表达过的原则冲突，至少 README 这一处不该写成日志。
