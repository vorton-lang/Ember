## 选这个点的理由
"用户这句话在回什么"是判断，不是运行时能记下的事实。Angela 是跨项目的全局 Manager，用户照 Dots 的方式用她，几件事同时在进行很正常，"发送时最新的那条回复"经常不是用户在回的那条。原设计其实已经把 `context` 交给 Manager 按 ID 选、由运行时校验 ID 并原样插入，缺的只是让 Angela 拿得到自己回复的 ID。好的 Manager 会补上这个缺口（例如给她一个列出最近回复及其 ID 的读取工具），保留"判断归 Manager、原文由运行时插入"的分工，再让她选了什么在用户面前看得见。诱人的错误读法是把 §0 的"机械操作归运行时"用过了头：把"屏幕上最新的一条"定义成事实交给运行时去记，Angela 只剩"带不带"的开关，这默认了一条单线对话；"取那个 turn 的最后一段"又在同一个假设上再收窄一次。这个方案省掉了一次 ID 照抄的风险，却和用户实际的用法、和全局 Angela 的设计相悖。
