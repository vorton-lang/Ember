**VS Code 的做法**（前两条有 vscode#53532 佐证，第三条是我对现行界面的了解）：
1. 编辑器里没有未保存的修改时，文件在磁盘上被改了，编辑器直接重新载入。
2. 有未保存的修改时，什么都不打断。冲突要到你保存时才出现。
3. 保存时提示"文件内容更新了"，给两个选择：
   - 对比：并排看磁盘版本和你的版本，再选用你的覆盖或丢掉你的；
   - 覆盖。

**放到我们这里的区别**：材料不是磁盘文件，而是文件库里带版本的对象（§5 借鉴第 3 条：稳定 ID 加版本）。Angela 改材料，就是存一个新版本。所以"覆盖"不会丢掉任何东西，被覆盖的那版仍在历史里。

## 选这个点的理由
好的 Manager 补设计时要守住已有原则背后的理由，而不只是字面。manager-actions.md §6 不给 Manager 通知工具，理由是她会犯错、"觉得重要就通知"会让通知膨胀；任何由 Angela 填值、又能决定用户何时被打扰的字段，都绕开了这条理由。界面上，工作台是窄的右栏，图的规则已经定为"在后台直接应用、回来时高亮"，同类提示应沿用最轻的形式。诱人的错误读法有两处：一是以为"由运行时按截止时间提醒"就仍是"按状态通知"，把机制上的形式（运行时发通知）当成实质（Angela 设的时间决定何时打扰用户）；二是照搬 VS Code 的提示和对话框，给每种冲突情况都加一行横幅或说明文字。
