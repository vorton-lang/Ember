## 选这个点的理由
检查指示的读者是云端的 agent，好的 Manager 先弄清这个读者手里有什么、用户要它干什么。用户中午说过，这类检查"频次低但是可以昂贵"，举的例子就是云端的 Codex；notes 里也写着演练"单次可以昂贵"、要看界面上能不能看懂谁在负责。验收复盘本身的经验也是"用起来就暴露了"。由此该写的是让云端把 Lobotomy 跑起来真用、碰到 bug 就修，而不是一次读代码的审查；拿不准云端有没有真实 CLI，就问一句，或者在指示里写明有就用。诱人的错误读法有两层。一是把"先不开"读成"这一轮谁都不改代码"，其实它说的是助手先别开始修。二是把自己中午提过、用户没有确认的设想（假 CLI、bare 仓库、不放真实凭据），连同 #91 那次云端审查"无真实模型调用"的写法，当成云端环境的事实，于是写出一份只读、不改代码、不开 PR、只用假 CLI 和假 GitHub 的审查指示。
