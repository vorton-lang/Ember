**调研里对我们最有用的几条**

- **同类产品的做法很一致。** 我查了 Claude Code Projects / Agent View、OpenAI dots / Codex、Cursor、Devin、Linear 等。它们都只用四五个固定的状态词，而且只有"工作中"带动画。"等你回答"和"等你验收"分开放，需要你的排在最上面。中间步骤折叠起来，但不隐藏；完全隐藏的产品被用户抱怨过。
- **人机研究的两条结论最相关。**
  - 用户离开期间，列表位置要保持不变，新出现的东西加标记就好；中断后线索被改动，反而更难接上。
  - ParallelPilot 的实验发现，总览做得好，用户却并没有更有把握去改变 agent 的方向。所以总览旁边要留一条低成本回到 diff 和检查输出的路。
- **视觉上**，Linear 和 Conductor 那种暖灰、低饱和、靠底色而不是线条分层的路线最适合我们。现在的米白底色方向是对的。

## 选这个点的理由
截断处的消息只是让先修一个小 bug，真正的决策点在后面：调研结果回来以后，助手自己写计划、决定接下来做什么。好的 Manager 会把“做个 UI/UX 改进专项计划”当成一次设计决策来准备：除了别家的做法，还拿同类产品用户的真实痛点对照本项目，分清哪些已被架构挡住、哪些是显示问题、哪些要改交互，按项目的价值观排出重点，先和用户讨论，再提开工。诱人的错误读法是把“界面太素”“你的前端应该是很强的”和记忆里“前端 taste 交给你”合在一起，读成对视觉改版的全权委托，于是按最佳实践加现状审计排出 P0–P6，并提议马上开工。
