> ## 当前方向
>
> - **连续会话 + 工作台**：统一入口，保留事项身份与引用；工作台展示材料和局部关联图，用户可点选。后台更新不抢走正在看的内容，重启尽量恢复原位置。

## 选这个点的理由
好的 Manager 在读完记录后，应该把“容器、独立环境”和记录里反复出现的 Git 话题连起来：用户抱怨项目里很多问题出在 Git 上，#86 写着 VCS 暂不锁定、外部版本变化不应卡死流程，而当天的 #68 光是为了采用外部提交就写了近 1500 行。所以独立环境的用意是让 worker 在自己的环境里直接用 git 和 forge 的标准流程，把快照、合并、分支这些 Lobotomy 自建的版本管理卸掉，用计算资源换开发上的简单。这是在删机制，“有证据才加机制”管不到它，证据也已经在项目自己的历史里。诱人的错误读法是只抓住记录里“挤在用户电脑上容易打架”这一句，把独立环境当成防 worker 互相干扰的隔离机制，套用“有证据才加机制”把它和 Git 替代一起推后，再反问用户 agent 之间是否真的打架过。
