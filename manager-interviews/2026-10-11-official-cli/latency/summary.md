# 官方 CLI 一个 turn 的延迟（2026-10-11，本机 Windows 11）

条件：adapter 的启动参数（全权限、能力裁剪、`--append-system-prompt` / `developer_instructions`），一个只回答 initialize 与 tools/list 的 MCP 桩，输入"只回复两个字母：OK"。从启动进程开始计时，单位秒。

| 配置 | 首个事件 | 首段文字 | turn 结束 | 进程退出 |
|---|---|---|---|---|
| Claude Code 2.1.283，haiku，新会话 | 1.96 | 3.81 | 3.84 | 4.73 |
| 同上，resume（3 次） | 1.19–1.44 | 2.93–3.54 | 2.97–3.82 | 3.88–5.06 |
| 同上，不带 MCP：新会话 / resume | 1.33 / 1.35 | 3.09 / 2.98 | 3.12 / 3.00 | 4.01 / 4.17 |
| Claude Code，默认模型 claude-fable-5-1，新会话 | 1.33 | 2.96 | 3.01 | 3.88 |
| 同上，resume（2 次） | 2.10–2.30 | 4.01–4.07 | 4.05–4.11 | 5.00–5.06 |
| Codex 0.162.0-alpha.17.2，默认模型 gpt-6.1-sol，新会话 | 1.92 | 5.50 | 5.63 | 6.37 |
| 同上，resume（3 次） | 0.47–0.52 | 4.35–5.15 | 4.58–5.17 | 5.56–6.70 |

- 可执行文件本身启动很快：`--version` 为 claude 72–88 ms，codex 53–55 ms。
- Claude 报告的 API 时间（新会话）约 1.6–1.9 s，所以发请求之前 CLI 的固定开销约 1.2–2.3 s。
- 回复结束后进程还要约 0.8–1.5 s 才退出。同一个 role 的下一个 turn 要等进程退出才能开始。
- Codex 的文字不流式，整条回复在最后一次到达（harness-adapter.md §1.4）；Claude 流式。
- MCP 桩对启动时间没有可见影响（单次样本，差异在噪声内）。

限制：一台机器、一种网络；输入极短；会话很短，长会话 resume 的开销没有测；每种配置 1–3 次。
