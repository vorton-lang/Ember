**为什么要先做多项目**

Angela 的三处基础，都取决于多项目做成什么样：

- **她的数据和 turn 放在哪里。** 现在一个后端进程只开一个项目（`lobotomyd --data-dir <项目>`）。项目外层只有 host.db，存额度域、权限和 CLI 配置，没有地方能跑"不属于任何项目的 role"的 turn。先做 Angela 的话，只能把她塞进某个项目的进程，或者为她另起一个进程。两种都是临时方案。
- **她的工具。** 建任务、发消息都要指明是哪个项目。按单项目先做，以后工具的参数要改。ledger 的作用域也定不下来：#23 §2 区分用户级和项目级。
- **界面。** Angela 的布局是主区和她对话，旁边是项目列表，"等你决定"跨项目汇总。只有一个项目时，这套布局没法验证。

现有代码对多项目比较友好：
- 项目范围的状态都挂在 `Project` 上，没有全局单例。data-model §10 当初就这样约束过。
- 跨项目的状态已经放在 `Host` 里。

主要改动在进程外壳、请求路由和 GUI。

**多项目设计要点（我的建议，技术层面）**

1. **进程**：一个后端进程管理所有项目，notes 中早已定过这个方向。
   - `backend.json` 和进程锁移到 host 目录，Electron 只启动这一个后端。
   - 额度域"同时最多一次检查"现在只在进程内保证，合成一个进程后就对所有项目成立。
2. **项目登记**：host.db 加一张项目表，记录 id、名称、数据目录、仓库路径和状态。现有 `gui.json` 指向的项目在首次启动时登记进去，数据目录不动。
3. **路由**：
   - GUI 用一条连接，请求带项目参数，推送也带项目标识。
   - MCP 地址改为 `/mcp/{project}/{token}`。
4. **新建项目**：用户在 GUI 中选仓库后，正在运行的后端直接打开新的项目实例，不重启。
5. **出错隔离**：一个项目打不开（迁移失败、目录丢失）时，只标记这个项目出错，其他项目照常运行。
6. **项目外的 role**：在设计中先定下 Angela 的位置。她的数据放在 host 目录下，复用项目库的 turn 表、消息表和命令层。M3 只写进设计，M4 再实现，这样 Angela 不需要临时方案。

2. **跨项目同时运行的 turn 要不要设上限？** 建议不设，额度域已经是实际的限制。真实使用中遇到问题再加。
