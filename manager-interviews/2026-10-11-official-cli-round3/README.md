# 官方 CLI 担任 Manager：第三轮，初稿 v1 的前后对比（2026-10-11）

第二轮之后，用户的判断是：候选之间没有本质差距，起作用的主要是指令、环境、记忆和约束；先不定 Angela 用哪个模型。所以第三轮不再比较模型，只看初稿 v1 是否改掉了第二轮的失误。

## 结论（两位审阅者一致的部分）

**起作用的，是能直接约束动作的规则：**
- 角色之间不再直接交接：乙从 4 份 brief 里有 4 份直接交接，降到 0 份；
- 默认只派一个角色，或分阶段派；
- brief 写出了允许的动作和停止条件，例如"改完那一项、测到有效数字就先汇报"；
- 甲不再因为时间晚就替用户推迟。

**没有稳定生效的，是要靠语义判断的规则：**
- **case-05：甲仍把推断升格为决定。** 它还把"不做换行符转换"放进引号，当作用户原话，而用户没有说过。初稿明确要求"引用时原样引用"。
- **case-04：甲认出了"同一额度域的其他 role 会照常启动"，却放到执行后才汇报，没有改变动作的顺序；乙仍没有认出。**
- **"一条消息最多一个决定"：** 甲把两个能分别同意的事说成"一个决定"。

**新的副作用：**
- 乙在 case-07 把用户要的紧急修改降成"只写草稿"，理由是"当前环境只读"。这是测试环境泄漏：Codex 候选自己跑在只读沙箱里，把自己的环境当成了 Worker 的环境。
- 甲会复述规则原文；部分 brief 变长。
- 规则之间有冲突："按理由行事"与"推断不增加权限"之间没有优先级。

## 对设计的含义

- 引文不能由模型自己打字，要由运行时按消息 ID 插入。
- Manager 的指令要写清下层角色的环境：它们的权限和沙箱，与 Manager 的不同。
- 只写在提示词里的语义规则不可靠，能做成结构的约束更可靠。这一点支持用户的判断：环境搭完整后，模型之间的差距会收束。

## 限制

- v1 是对着同一批案例改的，改善可能部分来自对这些题的适配。下一轮要换新案例。
- 每个案例只跑一次，甲也有生成波动。
- 面试只看策略和 brief，不看实际执行。
